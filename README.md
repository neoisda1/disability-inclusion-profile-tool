# Disability Inclusion Profile Preparation Assistant

An AI-assisted Disability Inclusion Profile preparation and evidence-organising tool for
Victorian government school staff. It is **not** the Department of Education's DIFS
Portal and is **not** an official or accredited Department system.

It helps a Disability Inclusion Coordinator, teacher, education support staff member or
school leadership team prepare strengths-based, functional-needs-focused, student-specific
information ahead of a Disability Inclusion Profile (DIP) meeting - and organise the
existing school evidence that supports it.

## Live demo

Enable GitHub Pages for this repository (Settings → Pages → Source: "Deploy from a
branch" → `main` / `/(root)`) and the site will be published at
`https://<your-username>.github.io/<repo-name>/`. No build step, server or database is
required - it is a plain static site.

## Important limitations (please read)

This runs entirely as static files on GitHub Pages, which has **no server and no
database**. That shaped several deliberate design decisions:

- **Data storage**: all student information is stored only in your browser's
  `localStorage`, on your device. Nothing is uploaded anywhere by this tool. Clearing
  browser data deletes it permanently - use the Export/backup buttons to keep a copy.
- **No real accounts**: there is no login, authentication or enforced role-based access
  (that would require a server). The role selector in Admin is a label only, not a
  security boundary.
- **No live AI calls**: the "AI interview" and drafting features are a rule-based
  wizard, not a call to an external AI model. This was a deliberate choice so that no
  identifiable student information ever leaves the browser. Every draft, "make this
  more specific" rewrite, red-flag check and quality check is generated by rearranging
  and checking text you typed in - nothing is invented.
- **Department content monitoring**: a scheduled GitHub Action
  (`.github/workflows/check-department-source.yml`) checks the Department's published
  Disability Inclusion Profile pages for changes and opens a GitHub Issue for a human
  to review. It never edits the app's content automatically.

Because of these constraints, only enter a real student's identifiable, health or
disability information once your school has approved the use of this software and
confirmed its privacy, information-security and records-management requirements are
met (see the in-app privacy notice and `About & Privacy` page).

## What it does

- Guided student intake: strengths, interests, motivations, aspirations, student voice,
  parent/carer input, and specialist evidence - each clearly labelled and kept separate.
- Functional-needs analysis across the Department's 6 profile domains, focused on
  functional impact rather than diagnosis (a diagnosis never automatically produces an
  adjustment level).
- Evidence organiser and interactive evidence matrix, with duplicate detection and a
  reminder of the Department's recommended maximum of 15 high-quality documents.
- A non-binding "possible adjustment level" indicator (differentiated / supplementary /
  substantial / extensive) that only surfaces which Department wording the entered text
  resembles - the final level is always left to the SSG/facilitator.
- "Make this more specific" rewriting, a red-flag scanner (absolute statements, vague
  descriptions, diagnosis-driven reasoning), and a quality checklist - all rule-based
  and grounded only in user-entered text.
- SSG meeting preparation, evidence-gap reporting, and export to Word-compatible `.doc`,
  CSV/Excel and print-to-PDF, every export labelled "AI-assisted preparation document -
  not an official Disability Inclusion Profile."
- An Admin/Content page so the Department Knowledge Base (`data/content.json`) can be
  updated without touching the app's code.

## Department Knowledge Base and sourcing

`data/content.json` is the single source of truth for Department terminology (domains,
adjustment levels/dimensions, supporting-information rules, process steps). It was built
directly from the Department's published policy and guidance pages (see the sources list
in `data/content.json` under `meta.sourceUrls`, and the in-app **About & Privacy** page).

**Known gap to fix before relying on this for a real meeting**: the Department's
*Functional Needs Domain Table* (the official list of all 31 school-related activities)
is published only as a PDF/DOCX and could not be machine-verified for this build. The
starter "activities" seeded under each domain in `data/content.json` are illustrative
placeholders only (`"verified": false`) - review them against the official table at
<https://content.sdp.education.vic.gov.au/media/disability-inclusion-functional-needs-domain-table-1417>
and correct them via the Admin page (or by editing `data/content.json` directly) before
relying on the activity list. Staff can also add their own custom activities in the app
at any time.

## Local development

No build tooling is required. Serve the folder with any static file server, e.g.:

```bash
python3 -m http.server 8000
```

Then open `http://localhost:8000/`.

## Project structure

```
index.html                 App shell, privacy modal, nav
css/styles.css              Styling (big buttons, accessible forms)
js/app.js                   Router + event handling (the only place that mutates data)
js/views.js                 Pure render functions (HTML strings) per screen
js/rules.js                 Rule-based "AI": drafts, red flags, quality checks, levels
js/store.js                 localStorage persistence for students/settings
js/content.js               Loads/merges the Department Knowledge Base
js/exportUtils.js           DOC/CSV/PDF export helpers
data/content.json           Department Knowledge Base (the "admin/content layer")
data/source-tracking.json   Hashes used by the scheduled change-detection Action
scripts/check_department_source.py   Script run by the scheduled Action
.github/workflows/check-department-source.yml   Weekly Department page monitor
```
